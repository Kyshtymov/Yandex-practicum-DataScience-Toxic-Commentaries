# Классификация токсичных комментариев для интернет-магазина «Викишоп»

## 📌 Описание проекта

Интернет-магазин **«Викишоп»** запускает новый сервис: пользователи могут редактировать и дополнять описания товаров, как в вики-сообществах. Клиенты предлагают свои правки и комментируют изменения других.

**Проблема:** вместе с полезными правками пользователи могут оставлять токсичные комментарии, которые необходимо оперативно выявлять и отправлять на модерацию. Ручная модерация большого потока комментариев невозможна.

**Решение:** построена модель машинного обучения для автоматической классификации комментариев на позитивные и токсичные.

---

## 🎯 Цель исследования

Обучить модель классифицировать комментарии на позитивные и негативные с метрикой качества **F1 ≥ 0.75**.

> ⚠️ **Важно:** для выполнения проекта **BERT не применялся** — использованы классические методы NLP (TF-IDF + линейные модели и деревья решений).

---

## 📂 Данные

**Файл:** `toxic_comments.csv`

| Признак | Описание |
|---|---|
| `Unnamed: 0` | идентификатор записи (сделан индексом) |
| `text` | текст комментария |
| `toxic` | целевой признак (токсичность) |

> ⚠️ **Ограничение:** из-за ограничения по оперативной памяти (ядро Jupyter постоянно падало при загрузке >10 000 строк) модели обучены на **10 000 событиях**. При использовании полной статистики точность должна статистически расти.

---

## 🔬 Ход исследования

### Шаг 1. Подготовка данных

**Загрузка и первичный анализ:**
- Загружен датасет `toxic_comments.csv` (10 000 строк).
- Изучена общая информация: типы данных, пропуски, распределения.
- Столбец `Unnamed: 0` содержит уникальные значения → сделан индексом.
- Проверка дубликатов и пропусков: не обнаружено.
- Распределение целевого признака `toxic` неравномерное (дисбаланс классов).

**Предобработка текста:**
- Приведение текста к нижнему регистру.
- Очистка от ненужных символов (регулярные выражения).
- **Лемматизация** с использованием `WordNetLemmatizer` и `nltk.pos_tag` (учёт части речи).
- Использованы стоп-слова из `nltk` (английские).

**Векторизация:**
- **TF-IDF** (`TfidfVectorizer`) с учётом стоп-слов.
- Построены матрицы признаков для train и test.

### Шаг 2. Обучение моделей

**Разделение данных:**
- `train_test_split` с `test_size=0.1`, `random_state=42`, `stratify=df['toxic']`.

**Рассмотренные модели и результаты кросс-валидации (cv=3, scoring='f1'):**

| Модель | F1 (кросс-валидация) |
|---|---|
| `DecisionTreeClassifier` (max_depth=5) | ~низкое значение |
| `LogisticRegression` (liblinear, l1, C=100) | ~среднее значение |
| **`PassiveAggressiveClassifier`** | **лучшее значение** |

**Лучшая модель:** `PassiveAggressiveClassifier` — выбрана по результатам кросс-валидации.

**Обучение лучшей модели:**
- Обучена на TF-IDF признаках тренировочной выборки.
- Проверена на тестовой выборке.

### Шаг 3. Тестирование

- **F1 на тестовой выборке: 0.76** ✅ (критерий ≥ 0.75 выполнен).

## 💡 Выводы для бизнеса

1. **Модель `PassiveAggressiveClassifier`** рекомендуется для внедрения в сервис модерации комментариев:
   - обеспечивает F1 = 0.76, что превышает требуемый порог;
   - быстро обучается и предсказывает;
   - эффективна на разреженных TF-IDF признаках.

2. **Ключевые особенности решения:**
   - предобработка текста (очистка, лемматизация) существенно улучшает качество;
   - TF-IDF хорошо работает для задачи классификации токсичности;
   - дисбаланс классов учтён через `stratify` при разделении.

3. **Рекомендации:**
   - использовать модель для автоматической фильтрации токсичных комментариев;
   - рассмотреть увеличение объёма обучающей выборки (в работе использовано 10 000 строк из-за ограничений памяти);
   - при наличии ресурсов — протестировать BERT или другие трансформеры для повышения качества.
